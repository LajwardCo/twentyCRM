# Surveys M1 — Form engine + provisioning Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A pure, tested form engine exported as `twenty-shared/surveys` (and aliased `@shared/surveys` in the Sales App), plus an idempotent provisioning script that creates every survey object/field/relation.

**Architecture:** Engine lives in `packages/twenty-shared/src/surveys/{types,constants,utils}` following twenty-shared's one-export-per-file + auto-generated barrel convention. It imports nothing outside `src/surveys` (the Sales App resolves it by source path, outside the yarn workspace). Provisioning follows `tools/sales-crm/provision-subscriptions-referrals-offers.mjs`.

**Tech Stack:** TypeScript, Jest (@swc/jest) in twenty-shared, Node 24 ESM script for provisioning.

Spec: `docs/superpowers/specs/2026-09-26-surveys-forms-design.md` (§3, §4).

### Task 1: Types and constants

Write `types/FormDefinition.ts` exactly per spec §4 (LocalizedText, FormLanguage =
'fa'|'ps'|'en', FormDefinition, FormPage, FormItem, Question, SectionBlock,

FormAudience = 'PUBLIC'|'STAFF').

`CrmMappingRule = { id; questionId; target: 'company'|'person'|'opportunity';
field: CrmTargetField }` with `CrmTargetField` a closed union of approved fields:
company.name, company.address, company.domainName, company.businessType,
company.employees, person.name, person.phone, person.email, person.jobTitle,
opportunity.name, opportunity.interest (appended to the lead note),
opportunity.followUp (becomes follow-up task text).

`AutomationRule = { id; when?: ConditionGroup; action: 'CREATE_LEAD' |
'CREATE_TASK' | 'NOTIFY'; assigneeMemberId?: string; taskTitle?: string;
dueInDays?: number; enabled: boolean }`.

Answer value union (`FormAnswers.ts`): string | number | boolean | string[] |
AddressAnswer | LocationAnswer | FileAnswer[] | ChoiceAnswer
where ChoiceAnswer = { choiceId: string; otherText?: string } for single choice
and `{ choiceIds: string[]; otherText?: string }` for multi choice.

Constants: `SURVEY_LIMITS = { maxTextLength: 10000, maxShortTextLength: 500,
maxChoices: 100, maxQuestions: 300, maxPages: 50, maxFileMb: 10 }`,
`SURVEY_RTL_LANGUAGES = ['fa','ps']`.

### Task 2: Answer primitives

`isAnswerPresent(question, value)`: false for undefined/null/''/whitespace, [],
choice without choiceId, multi with empty choiceIds and no otherText, address
with all parts blank, location without lat/lng and without manual text,
consent === false. True otherwise.

`normalizeAnswer(question, raw)` → `{ value } | { error: code }`: trims
strings, parses numeric strings for number/rating/opinion_scale, lowercases
email, strips unknown choice ids, dedupes multi, drops fields not in the
answer shape. Never throws.

Tests (write first):
```ts
it('treats whitespace text as unanswered', () => expect(isAnswerPresent(q('short_text'), '  ')).toBe(false));
it('treats unchecked consent as unanswered', () => expect(isAnswerPresent(q('consent'), false)).toBe(false));
it('parses numeric strings for number questions', () => expect(normalizeAnswer(q('number'), ' 12.5 ')).toEqual({ value: 12.5 }));
it('rejects a choice id that is not in the question', () =>
  expect(normalizeAnswer(choiceQ, { choiceId: 'c_nope' })).toEqual({ error: 'INVALID_CHOICE' }));
it('dedupes multi-choice ids', () =>
  expect(normalizeAnswer(multiQ, { choiceIds: ['c_a', 'c_a'] })).toEqual({ value: { choiceIds: ['c_a'] } }));
```

### Task 3: Conditions

`evaluateCondition(condition, answers, questionsById, visibleIds)`: an answer
of a question not in `visibleIds` is treated as absent. Ops:
answered/not_answered; eq/neq (choice id for single choice/dropdown, boolean
for yes_no, number/string otherwise); includes/excludes (multi choice id);
gt/gte/lt/lte (numbers only; absent → false). `evaluateConditionGroup` — ALL
(empty → true), ANY (empty → false).

Tests cover every operator, the hidden-question-as-absent rule and ANY/ALL.

### Task 4: evaluateForm

```ts
evaluateForm(def, answers, { audience }) => {
  pagePath: string[];              // page ids in visiting order
  visibleItemIds: Set<string>;     // items visible on pages in pagePath
  requiredQuestionIds: Set<string>;
  skippedByLogic: string[];        // questions in def (and audience) not visible
  endingId: string;
}
```
Algorithm: walk pages from index 0; for each page compute item visibility in
order (a question is visible iff audience allows it AND its section (if any,
the nearest preceding section on the page) is visible AND `visibleWhen`
holds against answers of already-visible questions); required = visible &&
(required || requiredWhen holds). Then evaluate the page's jumps in order —
first whose `when` holds decides: `{pageId}` → continue there (must be later;
if not later, ignore the jump — the publish validator reports it), `{end}` →
stop with that ending. No jump → next page. After last page, ending = first
ending whose `when` holds, else first ending without `when`, else first
ending. STAFF_ONLY items are invisible for PUBLIC audience and are **not**
listed in skippedByLogic for that audience.

Tests: brief's example (uses software? yes → "which software" visible; no →
hidden and "how do you manage records" visible), jump skips a page (its
questions in skippedByLogic), jump to end picks that ending, conditional
ending, section hidden hides its questions, staff-only invisible to public.

### Task 5: validateResponse

```ts
validateResponse(def, answers, { audience, mode }) => {
  cleanAnswers: Record<string, AnswerValue>;
  skippedByLogic: string[];
  errors: { questionId: string; code: ValidationCode }[];
  endingId: string;
}
```
Steps: drop unknown ids and ids the audience cannot see; normalize each;
evaluate form on normalized answers; drop answers of non-visible questions;
in COMPLETE mode add REQUIRED for visible required questions without answer;
per-type checks via `validateAnswerValue` (length min/max, number min/max,
selection min/max, email/phone/website format, date/time format, rating range,
file count/type/size meta, consent must be true when required). PARTIAL mode
keeps format errors only for present answers and never REQUIRED.
Codes: REQUIRED, TOO_SHORT, TOO_LONG, TOO_SMALL, TOO_LARGE, TOO_FEW,
TOO_MANY, INVALID_EMAIL, INVALID_PHONE, INVALID_URL, INVALID_DATE,
INVALID_CHOICE, INVALID_FILE, INVALID_VALUE.

Tests: hidden answer stripped and listed in skippedByLogic; required-when
enforced only when visible; PARTIAL never REQUIRED; staff question answer
dropped for PUBLIC; unknown id dropped; email invalid; multi maxSelected.

### Task 6: validateForPublish

Returns `{ errors: PublishIssue[], warnings: PublishIssue[] }`,
`PublishIssue = { code, itemId?, pageId?, ruleId?, message }` (message in
Dari — the engine owns the text so client and server agree). Checks:
EMPTY_FORM (no questions), DUPLICATE_ID, MISSING_LABEL (default language),
NO_CHOICES, BROKEN_REFERENCE (condition/jump/mapping/automation/ending refers
to missing question/page/ending), FORWARD_REFERENCE (condition refers to a
question at/after its target), BACKWARD_JUMP (jump to same/earlier page →
loop), CONTRADICTORY_JUMPS (identical `when` with different targets on one
page), UNREACHABLE_JUMP (rule after an unconditional jump — warning),
UNSATISFIABLE_REQUIRED (visibleWhen ALL containing two different `eq` on the
same single-choice/yes_no question, or `answered` + `not_answered`),
UNREACHABLE_PAGE (page no path reaches, via static reachability over jumps +
fall-through; required questions on it → error, otherwise warning),
PUBLIC_DEPENDS_ON_STAFF (public item/jump/ending condition references a
staff-only question), INCOMPATIBLE_MAPPING (question type not compatible
with mapped field — table in `proposeCrmChanges`), NO_ENDING.

Tests: one per code, plus the four starter-template-like fixtures pass with
zero errors.

### Task 7: toPublicDefinition + describeConditionGroup + analysePrintability

`toPublicDefinition(def)` → deep copy without STAFF_ONLY/crm_* questions,
without conditions/jumps/endings referencing them (a jump whose condition
referenced a staff question is removed), `crmMapping: []`, `automations: []`.

`describeConditionGroup(group, def, lang, numbering)` → Dari sentence, e.g.
`اگر پاسخ سؤال ۴ «بلی» است` / `… و …` / `… یا …`, with numbering = Map
questionId → printed number.

`analysePrintability(def, { audience })` →
`{ numbering, instructions: Record<itemId,string>, pageInstructions:
Record<pageId,string[]>, paperAlternatives: Record<itemId,string>, blockers:
PrintIssue[], notes: string[] }`. Instructions: item with visibleWhen →
"فقط در صورتی پاسخ دهید که …"; page jump → "اگر … به سؤال N بروید" (N = first
question number on the target page) or "… پرسشنامه را اینجا تمام کنید".
Paper alternatives: file, location, crm_*, datetime/time, image display.
Blockers: condition on a question whose paper form cannot express the
compared value (op gt/lt on non-numeric type); jump whose target page has no
numbered question and is not the end. Conditional endings → note ("پیام
پایانی فقط در نسخه آنلاین").

### Task 8: proposeCrmChanges + helpers

`proposeCrmChanges(def, cleanAnswers, existing: { company?: Record<string,unknown>; person?: …; opportunity?: … })`
→ `CrmProposal[] = { ruleId, target, field, questionId, proposed, current,
action: 'FILL'|'SAME'|'CONFLICT'|'SKIP_BLANK' }`. Blank proposed → SKIP_BLANK
(never clears), existing blank → FILL, equal (normalized) → SAME, else
CONFLICT (never auto-applied). Also exports compatibility table
`isMappingCompatible(questionType, field)`.

Helpers: `generateSurveyId(prefix)` (8 base62 chars via
`globalThis.crypto.getRandomValues`), `createEmptyFormDefinition(lang)`,
`duplicateFormItem(item)` (fresh ids for item and its choices),
`listFormQuestions(def)` (flat with pageId, sectionId, order),
`collectReferencedIds(group)`.
